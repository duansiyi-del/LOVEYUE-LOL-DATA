# LOVEYUE LOL DATA

线上地址: https://www.loveyue.xyz

车队战绩站, 基于 Next.js, 部署在 Vercel, 数据存 Vercel Postgres.

## 页面

- 首页
- 选手名单 `/roster`: 分路 / 英雄池 / 胜率, 全部按已同步对局自动统计, 不带筛选条
  (口径固定为全部对局; 想按赛段看去对位分析页)
- 战绩 `/matches`: 全队车队局列表, 含评分与详情页; 顶部是同步框
- 阵容分析 `/draft`: 我方常用英雄组合表现、最难打的对手英雄、五人阵容体检
- 对位分析 `/matchups`: 每个人在同一分路上对过的敌方英雄、双方 ban 位习惯
- 数据榜单 `/leaderboard`: 两个维度. 按成员看分位置, 按英雄看官方标签
  (坦克/战士/刺客/法师/射手/辅助). 指标跟着维度走 —— 辅助看视野控制, 坦克看承伤
  减伤, 射手看输出发育. 一律按每分钟或占全队比例 (总量只反映谁的局更长)
- 战队体检 `/report`: 总览 / 按车队规模 / 成员表现 / 各位置表现 / 在场缺席 /
  关键资源, 所有胜率都带 95% Wilson 置信区间
- 组队归因 `/attribution`: 某几个人一起打胜率低时, 把失利分成优势没转化 / 单点
  拖累 / 路人拖累 / 全线崩盘 / 打得胶着, 并指出谁最常掉队

## 数据从哪来

战绩来自**客户端本地接口 (LCU)**, 由那台开着客户端的 Windows 上的
`tools/auto_sync.ps1` 读出来, POST 给 `/api/matches/import` 入库
(格式转换见 `src/lib/lcu.ts`).

SGP (`src/lib/sgp.ts`) 之前一直返回 400, 对照一个真实可用的开源实现
(cridyy/lol-stats 的 `src-tauri/src/services/sgp.rs`) 后找到原因: **主机名必须小写**.
我们用的是 `GZ100-sgp.lol.qq.com`, 正确写法是 `gz100-sgp.lol.qq.com`; 网关对 Host
精确匹配, 对不上就一律 400 —— 这正好解释了「任何路径都 400, 连不存在的路径也是
400 而不是 404」. 另外不同大区规则不一样, 有的带 `-k8s-`, 映射表在
`matchesRoster.ts` 的 `SGP_BASE_BY_REGION`.

那份实现的注释还说明了为什么必须走 SGP: LCU 的
`/lol-match-history/v1/products/lol/{puuid}/matches` 在部分国服客户端上会忽略
`begIndex/endIndex`, 只能稳定拿到第一页 —— 和我们「只同步到 20 场」的现象完全吻合.

⚠ 覆盖范围: 只有跑脚本那台机器登录的账号打过的对局. 车队局只要有一个人在场,
十个人的数据都在; 想更全就在多个成员机器上各跑一份.

拿不到的东西 (都试过了):
- **10 分钟补刀差 / 经济差**: LCU 的 timeline 增量字段全是空的 (Riot 早就废弃),
  时间轴接口也没通. 现在的补刀差 / 经济差是整场结束时的值.
- **对手段位**: 对局数据里 `highestAchievedSeasonTier` 是空的, 排位接口只给
  登录者本人. 所以「这个组合胜率高是不是因为对手分低」暂时答不了.

大区、成员 puuid 在 `src/lib/matchesRoster.ts`. 拉取端尽量全存 (同一方 1 人起、2026-01-01 起);
**模式必须分开看**: 单双排 / 灵活 / 匹配的对局强度和匹配机制都不一样, 混在一起
统计会互相污染; 大乱斗更是另一回事 (没有分路、没有补刀概念); 自定义和人机不反映
真实水平. 所以模式是和门槛人数、日期同级的全局筛选, 默认【排位】(单双排+灵活),
所有数据页共用. 选项和分组在 `filters.ts` 的 `QUEUE_OPTIONS` / `QUEUE_GROUPS`.
名单页不带筛选条, 口径写死为排位全部对局.

⚠ 实现上用三个定长参数装模式名 (`queueSlots`), 不传数组 —— 这个驱动的 sql 模板
只保证基本类型可用. 目前最大的分组也只有两个模式, 三个位置够用且留了余量.

「几人算车队局」「从哪天看」是网页上的筛选参数 (`?min=3&since=&until=`),
默认值在 `src/lib/filters.ts`: 门槛 3 人、**时间不设下限**. 改参数只是重查库,
不动数据. 赛段快捷按钮在同一个文件的 `SEASON_PRESETS`.

## 阵容分析怎么算的

全部基于自己库里的对局, 不接第三方胜率数据:

- **英雄档案** (伤害构成 / 承伤占比 / 控制时长) 取【双方十个人】的行, 同样的对局
  数样本是我方的十倍; 只按时间过滤, 不按「同一方几名成员」过滤.
- **组合增益** = 两个英雄一起上的胜率 − 各自单独出场胜率的平均. 场次少于 5 场的
  不参与排名 (三五场的胜率是噪音).
- **阵容体检** 的阈值在 `src/lib/draftRules.ts` 的 `STRUCTURE_RULES` 一处, 判前排
  看承伤占比, 判控制看每场控制秒数, 判伤害单一看物理 / 法术加权占比.
- **对位** 按「同一分路 + 对面那边」配对, 只计召唤师峡谷. 补刀差 / 经济差是整场
  结束时的差值, 不是对线期的 -- 我们只拉了对局汇总, 没有时间轴数据, 一场滚雪球
  会放大差值. 排序用向 50% 收缩后的胜率, 少于 3 场不进排名.
- **大盘对位胜率** 来自 OP.GG 官方 MCP 接口 (`https://mcp-api.op.gg/mcp`, 不需要
  密钥, 见 `src/lib/opgg.ts`). 关键点: `lol_get_lane_matchup_guide` 返回的
  `data.counters` 是该英雄在该分路对上【所有】英雄的完整列表, 一次调用就够, 不用
  逐对去问. 英雄名要用显示名转大写下划线 (Wukong 的 Data Dragon key 是
  MonkeyKing, 用 key 查不到). 在对位页点「刷新大盘对位数据」触发, 或
  `curl -X POST <站点>/api/opgg/refresh`. 版本更新后刷一次即可.
  ⚠ 那是全球大盘、不分段位, 只能当参照系, 结论要以我们自己的数据为准.
- **ban 位建议** 按「遇到频率 × 胜率缺口」排序, 不是单纯按胜率低排 —— 那样三场
  全败的冷门英雄会顶在最前面, 而一个 ban 位该留给【又常遇到、又确实打不过】的.
  胜率缺口用向我们自己总体胜率收缩后的估计 (先验 6 场), 样本少时自动往中间靠.
  表里同时标出这英雄我们是不是已经在 ban, 以及区间是否完全低于总体 (是才算有把握).
  原始 ban 数据仍从 `matches.team_stats` 的 JSON 解析.
- **归因** 主判据是 `match_players.score` (rating.ts 在同一场十人之间归一化、按位置
  加权的 0~10 分), 不是经济: 输的一方每个人经济都低, 只看经济永远得出「大家都差」.
  阈值在 `ATTRIBUTION_RULES`. 没有 score 的老对局自动退回经济口径.

- **英雄标签** 来自 Data Dragon 的 `champion.json`, 是 Riot 官方分类, 一个英雄可能
  同时属于两类 (安妮是法师兼辅助, 寒冰是射手兼辅助), 所以按标签筛会有交叉, 这是
  对的不是 bug.
- **两个维度共用一次查询**: 取 (成员, 英雄) 最细粒度的【合计值】, 再在 JS 里折叠.
  两个原因: 一是用 `CASE WHEN <布尔参数>` 在 SQL 里切分组键行不通 —— sql 模板会把
  同一个布尔插成三个不同参数, Postgres 认不出 SELECT 和 GROUP BY 是同一个表达式,
  报 "must appear in the GROUP BY clause"; 二是必须返回合计值而不是平均值, 平均值
  再平均一次是错的.
- **占全队比例** 这类指标 (伤害占比/承伤占比/参团率) 的分母必须在【全队五人】上算.
  窗口函数要先在未过滤的行上求和再筛车队成员 —— 一开始把 `member <> ''` 写进了
  窗口那一层, 分母只剩车队成员, 参团率算出 278% 这种不可能的数.
- **置信区间** 用 Wilson 区间 (`src/lib/report.ts` 的 `wilson()`), 不用正态近似 ——
  小样本和 0%/100% 下后者会算出负数或超过 1, 而我们的场景天天是几场的样本.
  两个区间重叠就直接在页面上写「说明不了问题」, 不让人拿噪音当结论.

## 图表

纯 SVG 手写, 不引图表库. 两个组件:

- `RadarChart`: 六维能力图, **小倍数** (一人一张小图, 坐标轴和量程完全一致).
  没有把八个人叠在一张图上 —— 那么多条线颜色区分度和遮挡都会崩, 可视化规范里
  明确要求超过阈值就拆小倍数而不是硬加颜色. 每根轴按这批人的最大值归一化,
  所以外圈 = 本组第一, 是相对不是满分, 页面上写清楚了.
  不靠填充面积读数: 雷达图的面积没有实际含义.
- `IntervalChart`: 胜率 + 95% 置信区间误差棒. 换掉原来的「43% 30%~56%」文字写法
  —— 那要读者自己在脑子里比对两行数字有没有重叠. 画成误差棒后, 区间跨没跨过
  参照虚线一眼可见, 跨过的整行转灰, 不给"有差异"的暗示.

配色用 `globals.css` 里那套分类色, 已按可视化规范的六项检查跑过验证
(明度带 / 色度下限 / 色觉障碍区分度 / 常视区分度 / 对比度), 全部通过.

## 还没做 / 受限于数据

- **10 分钟补刀差 / 经济差**: 现在存的是整场结束时的差值, 一场滚雪球会放大它.
  真正的对线期指标要时间轴数据, 接口还没找到 —— 跑一次 `tools/run_probe.bat`
  会自动探测并把结果存到桌面.
- **对手段位 / MMR**: 现在库里没有任何段位字段, 所以「这个组合胜率高是不是因为
  对手分低」暂时答不了. 同一个探测脚本会把一场对局的完整原始 JSON 存下来, 看看
  返回里到底有没有段位, 以及有没有单独的排位接口可用.

## 工具包怎么发给队友

装客户端的那台 Windows 一般没代理也不方便连 git, 但它本来就能访问这个网站
(它就是往这儿同步战绩的). 所以工具包直接挂在网站上:

    https://www.loveyue.xyz/download

改完 `tools/` 下任何文件后, 跑一次 `npm run pack:tools` 重新打包, 再提交产物
(`public/download/LOVEYUE-sync.zip`). 打包脚本会把中文文件名换成英文
(中文名的 zip 在 Windows 上解出来常常乱码), 并拒绝任何非 ASCII 文件名.

## 加成员

1. 在 `tools/get_sgp_token.ps1` 的 `$RosterIds` 里加一行 `名字#编号`, 跑一次.
2. 把打印出的 `{ name, riotId, puuid }` 行贴进 `src/lib/matchesRoster.ts`.
3. 在 `src/lib/roster.ts` 里补一条: `nickname` 必须和游戏昵称完全一致 (战绩按它
   关联), `alias` 是平时叫的名字, 全站显示走 `displayName()`.

## 头像

图片放 `public/roster/` 下, 在 `roster.ts` 的 `photos` 数组里填路径. 一个人可以
放多张, 名单页卡片上能左右切换 (方向键, 或点两侧箭头 / 底部圆点); 只有一张时这些
控件不出现. 数组为空则显示别名首字的占位块. 竖版接近 4:5 最好, 会自动裁剪填充.

```ts
photos: ["/roster/p1.jpg", "/roster/p1b.jpg"],
```

## 本地开发

```bash
npm install
npm run dev
```

没有数据库时页面能打开但战绩为空. 有本地 Postgres 时把连接串填进
`.env.local` 的 `POSTGRES_URL`, 跑一次 `db/schema.sql`, 然后 `npm run dev:local`.

## 部署

Vercel 导入本仓库, Storage 接一个 Postgres 并 Connect 到项目, 然后在
Storage 的 Query 里执行一次 `db/schema.sql`. 没有其他环境变量.
